# OWASP Top 10 (2025) Hardening Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Bring the app up to the OWASP Top 10 2025 for an internet-facing deployment: no PDF reader, locked
dependencies, API rate limits, JSON errors with references, alerting, `__Host-` cookies, a tamper-proof change history
with an admin History page, and SECURITY.md rewritten for 2025.

**Architecture:** Server-side hardening in small modules beside the existing ones (`ratelimit.py` next to
`throttle.py`, `history.py` + `ChangeRecord` model, `alerts.py`), wired through `api.json_api` and model signals; one
new admin page built with `dom.js` like the others.

**Tech Stack:** Django 5.2, SQLite (dev) / PostgreSQL (prod), vanilla ES modules, jsdom smoke test, pip-tools.

**Spec:** `docs/superpowers/specs/2026-11-17-owasp-2025-design.md` (approved; incl. "Settled after the builder check").

## Global Constraints
- Internet-facing assumption. No new runtime service; e-mail optional (`DJANGO_ALERT_EMAILS`).
- CSP after Task 1: `require-trusted-types-for 'script'`, `trusted-types 'none'`, no `worker-src` line.
- History: every create / update / delete of Vessel, Service, HotelStay, Transfer, Guest, Option, ExchangeRate,
  Profile; one row per object (bulk + cascades included); kept forever; no update / delete path; PostgreSQL trigger.
- Rate limits count requests; writes fail closed, reads fail open; 429 with JSON `{"error": …}`.
- Every API error is JSON; unexpected ones `{"error": "Something went wrong.", "ref": "<8 hex>"}` and the ref is logged.
- `npm run check` green at the end of every task; smoke ×4 on a throwaway DB for tasks touching the front end.

## Review Focus
1. A port user must not read other ports' history (History API is admin-only → 403 for everyone else) — Task 5 test.
2. Bulk add of 200 rows still works under the rate limit (one request) — Task 3 test.
3. A failure inside the history write rolls the change back (no unrecorded change) — Task 5 test.
4. An unexpected exception in any API view returns JSON with a ref, never HTML — Task 4 test.
5. Old sessions after the `__Host-` rename: users simply sign in again (no 500) — Task 6 test.
